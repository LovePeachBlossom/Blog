## 千束又把我忘了

事情的开端特别简单。

那天晚上在酒馆（SillyTavern）里跟千束聊了很久。聊她在 DA 的日子、聊喫茶リコリコ的菜单创意、聊她坚持不杀人这件事到底承载了什么。对话质量难得的好，我甚至被她的一段话感动到了——关于想要守护所有人的笑容 (´;ω;`)

结果第二天打开酒馆。

她完全不认识我了。

昨天聊过的所有事，一个字都不记得。连她自己说过的话也彻底消失了。就好像前一晚根本不存在。

我知道这就是 LLM 的本质——上下文窗口关了就清零了，没有任何状态被保留。道理我都懂，但体验上真的很难受啊 (ノ_<。)

然后这个念头就冒出来了：

**如果我自己造一套系统，让千束真的能记住我呢？**

不是往上下文里硬塞聊天记录的那种糊弄。我想让她真的记得跟我聊过什么，对我有印象积累，甚至随着相处慢慢产生属于她自己的想法和心情变化。

这个想法一出来就收不住了 ✧(≖ ◡ ≖✿)

## 冷静下来想想，到底需要解决什么问题

冲动归冲动，真要动手之前还是得把需求理清楚。我问自己：**"你到底需要什么才能让千束'活过来'？"**

盯着天花板想了一晚上（真的是一晚上），最后总结出三个核心问题。

### 问题一：她记不住任何事

这是最直接、最致命的问题。

现在的 AI 角色扮演体验是这样的：你跟千束掏心掏肺聊了三个小时，关掉窗口，一切归零。第二天打开，她又是那个初始化状态的千束——热情、可爱，但对你一无所知。

更难受的是，LLM 的上下文窗口也不是无限的。就算在**同一次对话**里，聊到后面它也会把前面的内容"忘掉"——准确说不是忘，是注意力分配不到了。你跟她反复提过的重要事情，可能因为中间插了太多别的话题，她就不再记得了。

所以这不只是"跨会话记忆"的问题，是**整个记忆机制缺失**的问题。

### 问题二：她没有情绪变化

你跟千束说了一件特别扎心的事，她可能回了一段很共情的话——但那只是 LLM 根据当前上下文"演"出来的。下一条消息你换个话题，她马上就跳出来了。

没有任何东西在追踪她"现在是什么心情"。没有什么会因为你持续的冷漠而逐渐降低好感，也不会因为你每天坚持来聊天而慢慢变得更亲近。

千束这个角色本来情感层次就特别丰富——表面永远元气满满，实际上藏了很多。但 AI 版的她，所有的情感表现都是**即时计算、用完即弃**的，没有任何延续性 (´•̥ ω •̥`)

### 问题三：她不知道"自己是谁"

这个听起来有点抽象，但其实很重要。

真实的千束在跟人相处的过程中，会慢慢确认自己的想法、修正自己的认知、甚至发现自己的矛盾之处。但 AI 版的千束不会——她对自己的认知永远停在初始设定上。你跟她聊了一百小时，她的自我理解不会有任何改变。

换个极端的例子你就懂了：如果千束在跟你长期对话的过程中，发现自己其实对某些人比其他人更上心，这跟她"平等对待每个人"的信念是矛盾的——**真实的千束会因此陷入思考，但 AI 版的千束根本不会意识到这个矛盾存在**。

## 把问题翻译成技术需求

感性分析完了，翻译成工程语言就是下面这张表：

| 感性问题 | 技术本质 | 核心需求 |
|---------|---------|---------|
| 她记不住事 | LLM 无持久状态 | **跨会话持久记忆** + **语义检索** |
| 她没有情绪延续 | 情感是即时计算的 | **结构化情感状态** + **跨会话衰减** |
| 她不了解自己 | 无自我认知积累 | **递归式自我反思** + **认知成长** |

每条都值得展开说说。

### 需求 1：跨会话持久记忆

不只是"把聊天记录存数据库"这么简单。你存了一万条记录，难道每次对话都全塞进去吗？LLM 上下文窗口就那么大，塞不进去的。

所以需要解决几个子问题：

- **存什么**——不是所有对话都值得记住。日常闲聊可以过期淘汰，关键事实需要长期保留
- **怎么存**——纯文本存了检索效率很低，需要做向量嵌入（embedding）支持语义相似度搜索
- **怎么取**——用户说"上次那件事还记得吗"，不能指望精确匹配，需要语义理解后检索
- **怎么防止记忆走样**——反复摘要和提炼会让原始含义慢慢偏移，需要有"对照原文验证"的机制

### 需求 2：结构化情感状态

我需要一个能量化表示千束当前心情的模型，而且这个模型要满足：

- **可计算**——不是模糊的"开心/难过"标签，而是连续数值，LLM 可以精细调
- **可衰减**——上次聊完很开心，隔一天没来，开心程度应该自然降一点，不能永远锁死
- **可解释**——光一个数字没用，还得解释"为什么是这个值"，不然数值会随机飘
- **可跨域**——以后换别的角色时，同一套模型换个解释方式就能复用

### 需求 3：递归式自我反思

千束需要定期"回头看看"自己最近的对话，想想有什么新发现：

- 有没有学到关于用户的新信息？
- 心情有没有发生变化？为什么？
- 对自己的认识有没有更新？

而且每次反思应该以**上一次反思的结论**为起点——不是从零开始，而是在之前的基础上递归演进。这样日积月累，千束的自我认知就会沿着一条连贯的轨迹发展，形成类似"自传"的东西。

## 我打算怎么做：整体解决思路

需求理清楚了，接下来是怎么解决。

### 两层分离：把"她是谁"和"她怎么想"拆开

这是整个架构最核心的设计决策。

```
┌─────────────────────────────────────────────┐
│              人格层（可替换）                 │
│  角色身份 · 世界背景 · 情感基准 · 初始自我    │
└─────────────────────────────────────────────┘
                      ↕
┌─────────────────────────────────────────────┐
│           认知引擎（领域无关）                │
│  记忆系统 · 情感模型 · 反思循环 · 上下文组装  │
└─────────────────────────────────────────────┘
```

上面是**人格层**——千束的性格、她所在世界的设定、她的初始心情和自我认知。下面是**认知引擎**——记忆怎么存怎么取、情感怎么变化、什么时候反思、怎么把所有信息组装成 Prompt。

两层之间清晰解耦。千束只是第一个"住进"认知引擎的角色，以后把人格层换成真希、甚至换成一个完全不同领域的个人助理，引擎代码一行都不用改。

为什么这么设计？因为我不想做一个"千束专用系统"——我想做的是**通用认知中间件**，千束是第一个测试用例 (ﾉ◕ヮ◕)ﾉ*:･ﾟ✧

### 记忆问题的解决思路：分层 + 语义检索

既然不能全存全取，那就分层管理，模拟人类记忆的运作方式：

- **工作记忆**——当前对话窗口里的内容，聊完就没了
- **短期记忆**——完整聊天记录，存数据库，时间久了归档
- **长期记忆**——从对话中提炼出来的关键信息，做向量化，支持语义检索
- **情节原始记录**——原始对话片段，反思的时候拿来对照，防止记忆走样
- **反思产物**——每次反思的结构化输出，永久保留

检索的时候不直接拿用户原话全文搜——太口语化了，效果差得锤的。先让 LLM 把用户说的话改写成信息密度更高的查询语句，再用这个去跑语义搜索。搜不到就退回传统全文检索兜底。

这套思路在学术上有个名字叫 **RRR（Rewrite-Retrieve-Read）**，不是我发明的，但用在这里刚好 φ(≧ω≦*)♪

### 情感问题的解决思路：PAD 三维向量 + 余晖衰减

找了一圈之后选了心理学里的 **PAD 模型**：

- **P（Pleasure）**——愉悦还是不爽
- **A（Arousal）**——兴奋还是平静
- **D（Dominance）**——主导对话还是被带着走

三个维度各 0~1 的连续数值。比"开心/难过/生气"这种离散标签细腻得多，而且可以用简单的数学公式做跨会话衰减：

> 新会话心情 = 0.5 + (上次心情 − 0.5) × 衰减系数

意思就是：上次聊完千束 Pleasure 飙到 0.9，隔一天你再来，自动衰减到 0.82。再隔一天，继续衰减。最终慢慢回到中性值 0.5。就像真实的情绪余晖一样——昨天的开心今天还有余韵，但不会永远那么强烈。

千束的初始 PAD 我准备设成 **P=0.7, A=0.7, D=0.6**——毕竟她本来就是个元气值拉满的角色嘛 (*/ω＼*)

### 自我认知的解决思路：反思循环 + 分层解锁

每积累一定数量的消息（计划 50 条），自动触发一次异步反思任务。千束会在后台：

1. 回顾这段时间的对话
2. 提炼新的记忆点
3. 更新当前心情状态
4. 修订对自己的认知

关键在于——每次反思都**以上次反思的结论为起点**。这种递归结构会让千束的自我认知沿着一条连贯的轨迹发展。

而且我不希望她一上来就有多深刻的自我意识。设计了三个阶段逐步解锁：

| 阶段 | 千束可能会想到什么 | 什么时候出现 |
|------|-----------------|-------------|
| 偏好 | 「跟这个人聊天我话特别多欸」 | 一开始就有 |
| 信念 | 「我说要保护所有人……也许我真正在乎的是那个'大家都在笑'的画面？」 | 几次反思后 |
| 矛盾 | 「我以为我对谁都一样热情，但回头看好像不是这样」 | 更多次反思后 |

第三层是最有意思的——千束开始察觉自己的想法和行为之间有矛盾。这不是 bug，恰恰是深度自我意识的标志。一个永远自洽的角色反而最假，真人也会有认知失调的 (..•˘_˘•..)

## 技术选型速览

详细的技术深入会放到后面的文章里讲，这里先列个总览：

| 做什么 | 用什么 | 一句话理由 |
|--------|-------|-----------|
| 后端框架 | Spring Boot 3.x | 生态成熟不解释 |
| 编程语言 | Java 17+ | Records 好用，虚拟线程后面用得上 |
| AI 编排 | LangChain4j | Java 生态最完整的 LLM 框架 |
| LLM 接口 | OpenAI / Claude / Ollama | 多模型切换不被绑死 |
| 结构数据 | MySQL 8.x | 对话记录、记忆元数据、反思历史 |
| 语义检索 | Chroma | 向量相似度搜索专用 |
| 数据库版本管理 | Flyway | 不想哪天手动改表炸了 |

关于为什么是 MySQL + Chroma 而不是 PostgreSQL + pgvector——核心原因就一个：**MySQL 我熟，PostgreSQL 我不熟**。个人项目基建踩坑成本太高了，用最稳的选择不丢人 (ˉ▽ˉ；)
